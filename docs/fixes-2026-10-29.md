# 2026-10-29 작업 기록: Mr. Driller G AI 플레이어(TAS 봇) 조사 1차

코어(FPGA) 코드는 바꾸지 않았다. GroovyMAME(원본 mrdrilrg)에서 Lua로 조사하고 스크립트와 문서만 추가했다. 자세한 내용은 docs/drillerg-ai-plan.md.

## 목표
사람 없이 데모 화면부터 플레이, 랭킹 이름 "TAS" 입력까지 하는 AI 봇. 나중에 MiSTer OSD 오토파일럿, 2P 봇. 최종 봇은 맵 시드 난수 조작을 하지 않는다(사용자 결정).

## 가설과 확인 결과
1. 가설: 시작 순간 시드가 정해져 맵이 고정된다.
   - 확인: 스테이지 전체 맵이 시작 때 RAM 0x8031B8C0에 있다(1줄 = 필드 폭 바이트, India 7 / America 9 / Egypt·North 15). 플레이 입력이 달라도 맵은 같다. 캐릭터 선택에서 확정 버튼을 1프레임만 늦게 눌러도 맵이 완전히 바뀐다.
2. 의문: 맵의 캡슐 수가 퍼펙트 에어 조건보다 1개 적다.
   - 원인: 맨 위 시작 영역(6~7줄)은 고정 무늬로 덮이고 그 안에 캡슐 1개가 있다. 합치면 조건과 정확히 같다. 퍼펙트 에어 = 캡슐 전부 먹기.
3. 사용자 제보: 캡슐 재생성 버그(위로 10~13칸 올라갔다 내려오면 캡슐이 다시 생김).
   - 원인(코드로 확인, 실제 재현은 아직): 위로 스크롤(0x801E53BC)은 그리드(플레이어를 따라 움직이는 32줄 창, 링 버퍼 아님) 맨 아래 줄을 저장 없이 버리고, 아래로 스크롤(0x801E5204)은 그 줄을 맵 버퍼에서 다시 해독한다. 맵 버퍼는 플레이 중 쓰이지 않는다.
4. 블록 종류 변환표(코드): 0~3 색 블록, 4 X블록, 5 캡슐, 6 크리스탈, 7(America는 19) 화이트 블록. 레벨 구분 블록 0x6F15는 100m 직전 7줄.
5. 랭킹 등록: 깊이 먼저, 같은 깊이면 점수(실험). 깊이 0m/48m 고득점 해킹은 등록 안 됨, 317m 저득점은 등록됨.
6. 화면 흐름: 장면 번호 0x802D80A8, 캐릭터 커서 0x802AC980(육각형 고리), 스테이지 커서 0x802D80BC, 이름 입력 0x803BE724 등.

## 해결(결과물)
- tools/drgai/drgbot.lua: 무인 흐름 제어. 전원 켜기 → 코인 → 메뉴 → 타이조 → India → 플레이(임시 코드) → 이름 "TAS" → 다음 판. 2판 모두 클리어, 랭킹 1, 2위 TAS로 확인(별도 nvram, 테스트용 산소 고정).
- tools/drgai/ 조사 스크립트: g1probe.lua(그리드 덤프), seedprobe.lua(확정 프레임별 맵 해시), rtap.lua(읽기/쓰기 탭), flowprobe.lua(장면 기록), nametest.lua(이름 입력), menuexplore.lua(커서 탐색).
- 모든 실험은 세이브 복사본과 새 nvram 폴더로만 했다. 사용자 원본 세이브와 랭킹은 건드리지 않았다.

## 정정(같은 날)
- 처음에는 그리드를 32줄 링 버퍼로 보았으나, 실제로는 플레이어를 따라 줄을 복사해 움직이는 창이다. 그리드 줄 r = 게임 줄 (깊이 + r - 18)(India). 캡슐 재생성에 필요한 상승 칸 수는 계산상 15칸(사용자 기억 10~13칸, 재현 필요).

## 후반 작업: 블록 규칙 확인과 규칙 봇

### 낙하 오프셋
- 원인: +0x42 낙하 오프셋을 증가값으로 보았다.
- 실제: 블록은 새 줄에 바로 들어가고 오프셋 약 9088에서 낙하 속도만큼 0까지 줄어든다. 그려지는 위치 = 줄 - 오프셋/10240.
- 해결: 충돌 시간 식을 감소 방향으로 수정. 한 줄 = 10240, 속도 1152/1280/1536 /프레임.

### 위험 회피와 행동 취소
- 원인: 위험 회피와 하던 행동 취소가 서로 덮어써서 아무것도 못 하고 깔렸다.
- 해결: 위험 행동은 끝까지 수행한다.

### 지지 모델
- 가설: X 붙음, 수정 붙음, 벽 지지, 사라지는 칸 지지.
- 대조: 덤프와 비교. 사라지는 칸(5,6,8,9,10)과 얼어붙은 칸(7,12)을 고정 지지로 두어 오탐 10519 → 0.
- 결과: India 흔들림 시작 323개 예측 일치(놓침 15, 창 맨 위 줄), America 497개 일치(오탐 1, 놓침 24).

### 연쇄 사라짐 칸
- 원인: 연쇄 사라짐 칸(5/6)은 걸어서 못 들어가는데 봇이 들어가려 했다.
- 해결: 막힘 감지 추가(4+3프레임 x 변화 없음).

### X 블록 비용
- 원인: 공기 감소량 측정에 X 감소분이 섞여 비용이 틀렸다. X 블록 1개 = 약 -20800을 20프레임에 걸쳐(-1040/frame).
- 해결: 측정 오류를 고치고 X 블록을 5회 파기 + 공기 20%를 현재 감소 속도로 바꾼 프레임으로 비용화.

### 캡슐 목표
- 원인: 캡슐 목표를 깊이 점수에 섞으면 먼 캡슐만 노려 캡슐 수가 41 → 22로 줄었다.
- 해결: 가장 가까운 가치 있는 캡슐 우선으로 복귀.

### 조기 회피
- 가설: 150프레임 안에 위험이 오면 아래로 파지 않고 옆으로 피하면 좋다.
- 결과: 오히려 나빠졌다 → OB_EARLY로 꺼둠.

### 데모
- 데모는 개발자가 녹화한 입력 재생이다. 플레이어 열 아래를 X 블록으로 바꿔도 방향 바뀜 프레임이 그대로였다.

### 평가 (OB_CDELAY 12개 맵, Taizou)
- 클리어 5/12, 깔림 26회, 공기 0 8회, 평균 깊이 약 405m, 클리어 평균 타이머 약 10500. (처음 배치 봇은 39m에서 깔림)
- 남은 깔림의 대부분: 떨어지는 덩어리가 아래로 계속 파는 플레이어를 같은 속도로 따라오는 경우, 옆 칸으로 걷는 중 깔림.
