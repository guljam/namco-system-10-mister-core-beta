# CPU 1.5배(50.8 MHz) 계획

작성 2026-10-21. 상태: 계획(코드 변경 전).

## 1. 목적

- 실기 System 10의 CPU는 50.7 MHz다(MAME `namcos10.cpp`: XTAL 101.4912 MHz / 2). 코어는 PSX와 같은 33.8688 MHz로 돌고, 지금까지는 OSD "CPU Turbo"(메모리 대기 단축)로 보완했다.
- 목표: CPU를 clk2x(67.7376 MHz)에서 4클럭 중 3클럭만 동작시켜 50.80 MHz(실기 대비 +0.1%)로 만든다.
- 판단 기준: 좌상단 프레임 시간 표시(디버그 빌드, `rtl/gpu_frametime.vhd`)에서 프레임 누락(빨간색)이 줄어드는지 확인한다. 화면 / 소리 / 타이밍 문제(VSync 타임아웃 등)가 새로 생기지 않아야 한다.

## 2. 출발점: 업스트림 PSX_MiSTer `2xCPU` 브랜치

- `refs/heads/2xCPU` (cbefef4, README "Experimental build only"): CPU + GTE + 데이터 캐시 + 스크래치패드를 clk2x로 옮겨 CPU를 2배(67.7 MHz)로 돌린다.
- 바뀐 파일: `cpu.vhd`(약 500줄), `gte.vhd`(170줄), `datacache.vhd`, `dpram.vhd`(1클럭 dpram 추가), `psx_top.vhd`(clk2xIndex 연결, 리셋 후 16클럭 대기), `irq.vhd`(SS_idle).
- 우리 쪽 상태: `gte.vhd`, `datacache.vhd`, `dpram.vhd`는 업스트림 main과 동일. `cpu.vhd`는 main과 NS10 수정 35줄만 다르다.
  - 4 MB RAM(데이터 캐시 태그 주소 1비트 추가, `dma_cache_Adr` 22비트)
  - I/O·EXP 쓰기를 데이터 캐시에서 제외(워치독 0x1FB60000, 보드 SRAM 0x1F500000이 RAM 줄과 겹침)
  - PSY-Q VSync 대기 루프 타임아웃 2배(캐시 터보일 때, `00052BC0` → `00052C00` 명령어 교체)
- 따라서 2xCPU 판 4개 파일을 가져오고 NS10 수정 35줄을 다시 얹는 것이 가장 적은 변경이다.

## 3. 1.5배로 만드는 방법

- 2xCPU는 CPU가 clk2x 매 클럭 동작한다고 가정한다. 1.5배는 CPU 내부 `ce`에 4클럭 주기 패턴(1110)을 곱해서 만든다.
- 디버그 빌드에서는 OSD로 1배(1010) / 1.5배(1110) / 2배(1111)를 고를 수 있게 한다. 한 번의 빌드로 같은 장면을 세 속도로 비교할 수 있다. 1배 패턴은 기존 CPU와 같은 속도라서 기준선 역할을 한다.
- 문제: 2xCPU는 clk1x 쪽 신호를 특정 clk2x 클럭에서만 본다.
  - `mem_done = mem_done_in and clk2xIndex`: CPU가 멈춘 클럭에 오면 놓친다 → 래치해서 다음 동작 클럭까지 유지.
  - `mem_request`를 clk2xIndex에 맞춰 내리는 핸드셰이크 → 메모리 인터페이스 프로세스는 패턴과 무관하게(전체 `ce`로) 돌린다.
  - 쓰기 FIFO 푸시는 `clk2xIndex = '0'`일 때만 → 1110 패턴에서 clk2xIndex = '0' 클럭은 항상 동작하므로 그대로 된다.
  - `irqRequest`, `dmaStallCPU`는 clk1x 레벨 신호라 그대로 둬도 된다(확인 필요).
- VSync 루프 패치: 1.5배에서는 실기와 같은 속도이므로 원래 타임아웃이 맞아야 한다. 캐시 터보와의 조합은 시뮬과 실기로 확인한다.

## 4. 위험

- 타이밍: 우리 설계는 업스트림보다 크다(NS10 보드 로직, clk2x SPU). CPU 내부 최장 경로는 clk1x 기준 20.8 ns였고, clk2x는 14.76 ns 안에 들어와야 한다. 업스트림 2xCPU는 `lateRead` 경로 제거 등으로 이 조건을 맞췄다. 먼저 단독 CPU fit 또는 전체 빌드로 확인한다.
- 게임 동작: 실기 속도에 가까워지는 것이므로 원칙적으로는 좋아지는 방향이지만, 코어의 다른 부분(DMA, GPU 대기, 메모리 대기 모델)은 PSX 기준이다. MAME 동작을 기준으로 비교한다.

## 5. 검증 계획

1. GHDL로 CPU를 포함한 시스템 시뮬(psx_top + NS10 BIOS ROM)을 만들고, 기존 clk1x CPU와 새 CPU(1배 패턴)의 명령어 / 레지스터 쓰기 순서가 같은지 비교한다. 이어서 1.5배 / 2배에서 같은 프로그램이 같은 결과를 내는지 확인한다.
2. 디버그 + 릴리즈 병렬 빌드, 타이밍(4개 코너) 확인.
3. 실기: 4개 게임 × 속도 3개, 프레임 시간 표시와 SPU 프로브(EA 없음)로 비교.
