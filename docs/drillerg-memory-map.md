# Mr. Driller G (mrdrilrg, 원본 롬) 메모리/코드 맵

2026-10-28 GroovyMAME(namcos10.exe, 원본 mrdrilrg) 세이브 상태에서 RAM 덤프 + Lua 쓰기 탭 + capstone 역어셈으로 확인했다. 주소는 kseg0(0x80xxxxxx)다. 게임 코드는 부팅 때 복호화되어 RAM 0x80030000 이후에 올라가므로, 롬 파일 오프셋이 아니라 RAM 주소로 봐야 한다. 표의 "확인" 컬럼은 실측(MAME로 값이 바뀌는 것을 직접 확인) 또는 코드(역어셈으로만 확인)를 뜻한다.

2026-10-30 갱신: AI 봇 작업(docs/drillerg-ai-plan.md, docs/fixes-2026-10-29.md, docs/fixes-2026-10-30.md)에서 찾은 주소를 추가했다(플레이어 상태 4, 화면 흐름, 맵 버퍼, 그리드 칸 필드, 플레이어-블록 규칙).

## 1. 점수는 저장되지 않는다 (합산식)

점수는 RAM 어디에도 저장되지 않는다. HUD가 매 프레임 0x80212AE4에서 다음 식으로 다시 계산해서 표시한다.

- 점수 = 0x80369EBE(s16 지저인 수)×765 + P+0x124(산소 점수 누계) + P+0x128(판 블록 수)×10 + P+0x12C(연쇄로 사라진 블록 수)×30 + P+0x18(클리어 보너스 합) + 레벨보너스표[min(깊이/100, 50)] + max(0, 깊이/100 - 50)×50000
- 레벨보너스표 = 0x802A1EC0, u32×51: 0, 1000, 3000, 6000, 10000, 15000, ..., 1275000 (누적 레벨×1000)

검증 예(사용자 세이브 1, North 2000m 종료 시점): 546000 + 103330 + 253170 + 56×765(42840) + 210000 + 394000 = 1,549,340.

## 3. 레벨 파라미터 기록

0x801FDE08(인자 = 레벨 번호)이 모드별 표에서 u16 14개짜리 행(0x1C 바이트)을 골라 0x80337B20 + 플레이어×0x44 에 기록하고, 0x801FE2B4 / 스테이지 시작 코드가 그것을 플레이어 구조체 +0x168로 복사한다.

t0~t13 은 레벨 표 한 줄(레벨 1개)에 들어 있는 u16 값 14개를 앞에서부터 0번, 1번, ... 으로 부른 것이다. 공략 문서(drillerg-score-strategy.md)에서는 이 번호 대신 게임 용어를 쓴다: t0 = 블록 흔들림, t1 = 블록 낙하 속도, t3 = 산소 감소, t7 = 걷기 속도. 게임 시간으로 바꾸는 식: 산소 %/초 = t3 × 0.06, 낙하 프레임/칸 = 10240 / t1, 걷기 프레임/칸 = 10240 / t7, 흔들림 초 = t0 / 60.

| 표 칸 | 플레이어 오프셋 | 의미 |
|---|---|---|
| t0 | +0x196, +0x19A (u16) → +0x15C | 블록 흔들림 프레임(받침을 잃은 블록이 떨어지기 전) |
| t1 | +0x190, +0x194 (u16) → +0x15E | 낙하 속도(칸 = 10240 단위/프레임, 블록과 플레이어 공통) |
| t2 | +0x1A4 (u16) | 생성기 파라미터(의미 미확인) |
| t3 | +0x1A0 | 산소 소모(1프레임당 AIR 감소 = (t3 × P+0xB0) >> 8, 소수점 버림, 0x801F8DE8. P+0x120 ≠ 0이면 감소 안 함) |
| t4 | +0x1A8 | 생성기 파라미터(1~4; 1은 특수 레벨로 추정) |
| t5 | +0x170 | 항상 4 |
| t6 | +0x16C | 화면 레벨 번호(1부터) |
| t7 | +0x18C | 걷기 속도(× P+0xB4 / 256) |
| t8 | +0x168 | 생성기 파라미터(보통 2500~5000; 500/1000은 특수 레벨로 추정) |
| t9 | +0x1A6 (u16) | 생성기 파라미터(의미 미확인) |
| t10..t13 | - | 사용처 미확인 |

+0x19C = 152000 고정(최대 산소).

표 위치(행 = 난이도 0..4, 열 = 레벨)

- India(mode 13) 0x802A0598, 5행×5레벨, 난이도 = 0x803C58A4
- America(mode 12) 0x802A0138, 5행×10레벨, 난이도 = 0x803C58A5
- Egypt/North(mode 11) 0x8029F648, 5행×20레벨, 난이도 = 0x803C58A6, 단 0x8032688C(북극 플래그) = 1이면 행 4 고정
- mode 14/21 0x802A07C8
- mode 18/22 0x802A0D44
- mode 15-17,19,20 0x802A0DE8

운영자 난이도 설정 기본값은 1이다(덤프의 0x803C58A0.. = 00 00 00 01 01 01 01 01 01 02 01 ...). America 표의 행 4는 India 표를 그대로 복사해 놓은 것(개발 흔적)이다.

레벨 파라미터가 바뀌는 깊이(실측): 87/89m, 187/189m, 289m — 100m 경계보다 11~13m 앞이다.

### 4.1 플레이어-블록 규칙(실측, AI 봇 시뮬에 반영)

- 입력 지연 3프레임. 파기는 버튼 누름 엣지(& 0x200, 0x801F6CB4)에서만, 쿨다운 P+0x01. 착지 다음 프레임에 누르면 가장 빠르다(착지 동기 연사 = Drill(Auto)). X블록은 1프레임 간격 on/off로 2프레임마다 1타.
- 깔림: 블록이 플레이어 칸에 내려앉은 다음 프레임(낙하 오프셋 0)에 상태 7. 플레이어가 칸 중심에서 |x| >= 2912(P+0xEC) 벗어나 있고 그쪽 옆 칸이 비어 있으면 깔리지 않고 그 칸으로 밀려난다(x = 0, 상태 4, P+0x10C = 60). |x| 1504에서는 깔림.
- 파는 중인 칸(상태 8/9/10)으로는 옆으로 걸어 들어갈 수 없다(빈칸이 된 프레임부터). 연쇄 사라짐 중인 칸(5/6)도 들어갈 수 없다.
- 같은 프레임에 착지한 같은 색 블록은 그 프레임의 파기 덩어리에 들어가지 않는다(옆 칸을 파는 순간 착지한 블록에 깔리는 원인).
- 산소: 캡슐 = P+0x164에 +23000(매 프레임 +1000, 23프레임, 최대 152000), X블록 = -20000(매 프레임 -1000, 20프레임). India 기본 감소 24/30/37/40 per frame(0-200 / 200-300 / 300-400 / 400-500m, 타이조 기준).
- 지붕(사용자 규칙): 정착한 같은 색 덩어리가 다른 칸 위에 얹혀 있으면 그 아래 칸을 파도 떨어지지 않는다. 떨어짐과 연쇄가 끝난 뒤의 지붕 아래 열은 안전하다.
- 깊은 곳 진행 속도 약 12프레임/m(이상값 약 11.7).

## 5. 캐릭터 표

0x8029EFB8 산소 배율 u16×8, 0x8029EF98 걷기 배율 u16×8, 0x8029EFA8 대체 걷기 배율(아이템 처리 0x801E5C10에서 사용, 호링거는 208 유지).

## 6. 결과 화면 보너스

- 목숨 = P+0x88 × 30000 (0x8020CAD4)
- 시간 = 기준 - floor(P+0x98 / 6) × 50, 0 미만이면 0 (0x8020D100) — 기준은 India 150000(5분), America 300000(10분), 2000m 600000(20분)
- 퍼펙트 에어 = 50000, 조건은 P+0x8A >= India 56 / America 80 / 2000m 104 (0x8020CEAC)

실측 검증: India 자동 완주 7448프레임 → 150000 - 1241×50 = 87950, 목숨 2 → 60000, 캡슐 8개 → 퍼펙트 0.

## 7. 익스텐드(1UP)

0x80212CB8에서 처리한다. 기준 점수 표는 0x802A1E9C = 300000(mode 11), 0x802A1EA4 = 200000(mode 12), 0x802A1EAC = 100000(mode 13), 0x802A1EB4 = 400000, 1000000(mode 14)이다. 점수가 기준 이상이 되면 P+0x68 = 1, P+0x66++ 로 대기시키고, 다음 일반 블록 파기(종류 0x0F12 / 0x6F15 제외) 때 1UP 지저인이 등장한다: 목숨 +1, 지저인 수 +1(765점).

## 10. 랭킹 기록 (NVRAM에서 불러온 RAM 사본)

0x803C1E10부터 레코드 24바이트(0x18) × 10개씩, 표 5개: India, America, Egypt, North, 엔드리스 순서다. 같은 내용이 0x803A1D.., 0x803C76.. 에도 있다.

| 오프셋 | 형 | 의미 |
|---|---|---|
| +0x00 | u32 | 순위(1~10) |
| +0x04 | char[4] | 이름(3글자) |
| +0x08 | u32 | 하위 바이트 = 캐릭터 번호, 다음 바이트 = 클리어한 스테이지(1 India, 2 America, 3 Egypt, 4 North, 0 = 클리어 못 함/엔드리스) |
| +0x0C | u32 | 깊이(m) |
| +0x10 | u32 | 점수 |
| +0x14 | u32 | 시간: 바이트0 = 분, 바이트1 = 초, 바이트2 = 1/100초 |
