# 2026-11-13 좌우 검은 테두리 (GitHub 이슈) - OSD "Side Borders" 추가

## 증상 (GitHub 이슈, DE10-Nano 사용자)

- 1280x1024 LCD (`video_mode=4`, `vscale_mode=0`), Aspect ratio "Original", Scale "Normal".
- 화면 좌우에 검은 테두리가 있어 다른 4:3 아케이드 게임보다 화면이 좁다 (약 9%). MiSTer.ini로 없앨 수 없다.
- MiSTer 스크린샷 (`echo screenshot > /dev/MiSTer_cmd`, mrdrilrg): 코어 출력 563x480, 게임 화면 512x480,
  왼쪽 30 / 오른쪽 21 픽셀이 검다 (중앙에서 오른쪽으로 치우침).
- 요청: 표시 영역만 남기는 Crop / Overscan 옵션 (화면 비율은 표시 영역 기준), 또는 최소한 중앙 정렬.

## 원인 (버그 아님, PSX 코어에서 물려받은 설계)

1. `NAMCOS10.sv`의 `hb_start_lut` / `hb_end_lut`는 가로 해상도별로 **고정된** DE 창을 만든다.
   512 모드는 h_pos 50..613 = 563 픽셀 (= 2815 GPU 클럭 ≈ NTSC 한 줄의 표시 구간 52.6 µs).
2. 화면 비율 표 `aspect_ratio_lut_ntsc`는 이 563 픽셀 창 전체를 4:3으로 본다 (일반 TV에 비친 모습).
3. 게임은 GP1(06) 표시 범위 X1..X2 = 2560 클럭 = 512 픽셀만 그린다. 나머지 51 픽셀은 검다.
   30/21 치우침은 게임의 X1 위치와 고정 창의 위치 관계 때문이다 (실제 CRT라면 H-Position 손잡이로 맞추는 부분).
4. 같은 표가 PSX_MiSTer, ZN1, ZN1-Capcom, System573, SYSTEM11, Tenkomori, 다른 개발자의 Namco_S10 코어에
   글자 하나 다르지 않고 들어 있다. PSX 코어의 OSD "Horizontal Crop"은 프레임버퍼 폭을 넘는 쓰레기 픽셀만
   검게 칠할 뿐 창 크기는 줄이지 않는다 (`gpu_videoout_async.vhd`의 `hCrop`).
5. MAME (`src/devices/video/psx.cpp`)은 화면 폭 = 512로 잡고 4:3으로 보여 준다 (2560 클럭 = 4:3 전체 폭).
6. 개발자 환경 (CRT + 16:10 HDMI)에서는 테두리가 CRT 여백 / 양옆 검은 띠와 섞여 눈에 띄지 않았다.
   5:4 모니터는 폭이 기준이 되므로 게임이 9% 좁아진 것이 바로 보인다.

## 해결 (OSD Video & Audio → "Side Borders", status[43:42], HDMI 스케일러 쪽만)

| 설정 | DE 창 | 화면 비율 ("Original") |
|---|---|---|
| Keep (TV), 기본값 | 기존 고정 창 (512 모드 563 폭) | 기존 표 |
| Keep (centred) | 같은 폭, GPU가 실제로 그리는 구간 [gpu_hs, gpu_he)의 중앙에 맞춤 | 기존 표 |
| Crop (4:3 fill) | GPU 자신의 hblank (`psx_hbl`) = X1..X2 그대로 (Driller 게임 512) | 4:3 (MAME와 같음) |

- `gpu_hs` / `gpu_he`: 보이는 줄에서 `hbl` 1→0 / 0→1 순간의 `h_pos` (CE_PIXEL마다). 측정 전이거나
  계산이 음수가 되면 기존 LUT 창을 쓴다.
- Crop의 4:3 고정은 표시 범위가 2560 클럭인 게임 기준이다 (두 Driller 게임). 범위가 다른 게임이면
  비율을 (X2-X1)/2560에 맞춰 계산해야 한다 (지금은 필요 없음).
- 아날로그 CRT 출력: CRT Adjust Off (기본값)면 세 설정 모두 같은 화면이다 (테두리는 원래 검은색).
  CRT Adjust On이면 H-Size가 `hb` 창을 기준으로 다시 샘플링하므로 늘이고 줄이는 기준점이 게임 화면 중앙이 된다.
- `video_freak`의 `CROP_SIZE`는 세로 전용이라 쓸 수 없다.

## 검증

1. GHDL `sim/gpu/tb_video.vhd` (`sim/gpu/ghdl_video.sh [X1 X2]`, 약 10분): 실제 GPU RTL, 512x480i,
   X1..X2 = 0x260..0xC60, VRAM 전부 비검정. NAMCOS10.sv의 DE 로직을 VHDL로 옮겨 세 설정을 동시에 측정.
   시뮬레이션 시간 80 ms 제한 + 정지 워치독 + 15분 wall clock 제한.
   - Keep 563 폭 28/23, centred 563 폭 26/25, Crop 512 폭 0/0, 잘린 픽셀 0 → PASS
2. 실기 (디버그 빌드, mrdrilrg 원본 MRA, MiSTer 스크린샷):
   - Keep 563x480 30/21 (이슈와 정확히 같음), centred 563x480 26/25, Crop 512x480 0/0
   - 시뮬레이션 Keep 28/23과 2 픽셀 차이: Driller G의 X1이 표준 0x260보다 약 10 클럭 뒤라서다.
     centred / Crop은 GPU 구간 기준이라 X1과 무관하게 시뮬레이션과 실기가 같다.
3. 1280x1024 출력 (`[SYSTEM10]` 섹션 `video_mode=4`, `vscale_mode=0`)에서 사용자 확인.
   Crop: 4:3이 1024 높이 기준 1365 폭 > 1280이므로 폭 기준 1280x960을 게임이 꽉 채운다.

## 코어 수정 없이 쓸 수 있는 대안 (이슈 답변용)

`MiSTer.ini`에 `custom_aspect_ratio_1=563:384` + OSD Aspect ratio `[ARC1]` → 게임 부분이 정확히 4:3
(563/512 × 4/3 = 563/384). 16:9 / 16:10에서는 충분하지만 5:4에서는 높이가 약 873줄로 줄어든다.
