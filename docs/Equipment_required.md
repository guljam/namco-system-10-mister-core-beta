# Namco System 10 실기 기판 측정에 필요한 장비

- **작성일:** 2026-10-23
- **목적:** 실기 기판으로 정확한 타이밍과 동작 자료를 측정해 문서화하기 위한 장비와 방법 정리.
  MAME에도 없는 값(IRQ10 실제 주기, GPU 실제 그리기 속도, ROM 버스 대기 등)을 실측해서 코어 수정과 다른 개발자 공유의 근거로 쓴다.

## 1. 측정해야 할 값 (현재 열린 질문)

| 항목 | 현재 상태 | 코어에서 관련된 부분 |
|---|---|---|
| CPU / GPU 클럭 | MAME 값 50.7456 MHz(101.4912 MHz ÷ 2), 실측 안 함 | CPU Turbo, GPU 속도 가정(PSX의 1.5배) |
| IRQ10 주기와 VBlank와의 위상 | 미확인. 우리 코어는 2x VBlank, MAME는 100 Hz | `rtl/ns10/ns10_io.sv`, Drill (Auto) 연사 속도 |
| GPU 프리미티브별 그리기 시간 | MAME / DuckStation 모델 추정만 있음 | Gamshara / Star Trigon 480i 필드 초과 |
| ROM(EXP1) 읽기 대기 사이클 | MAME 기준으로 맞춤 | ROM 버스 대기 수정(de9062d) |
| 비디오 타이밍(라인 수, 필드 순서) | 코어 값 사용 | HDMI / CRT 출력 |

## 2. 장비 (우선순위 순)

### 1순위: 오실로스코프 (100~200 MHz, 4채널)

- 예: Rigol DHO804 / DHO914, Siglent SDS1104X-HD (50~80만 원대)
- 측정할 수 있는 것:
  - 수정 발진기 주파수: CPU / GPU 50.7456 MHz 확인
  - 비디오 H / V 동기 주기, 240p / 480i 라인 수, 필드 순서
  - **IRQ10 실제 주기**: 2x VBlank와 100 Hz 중 어느 쪽이 맞는지. 아직 확인하지 못한 핵심 항목이다.
  - 입력 신호에서 화면 반응까지의 지연
- IRQ 핀과 VSync를 함께 잡으면 IRQ10과 vblank의 위상 관계를 바로 볼 수 있다.

### 2순위: 테스트 코드를 기판에서 실행할 수단 (비용 대비 효과가 가장 큼)

- 필요한 것: ROM 라이터(예: XGecu T48 / T56, 10~20만 원대)와 기판의 ROM / 플래시 패키지에 맞는 소켓 어댑터
- 방법: 작은 테스트 프로그램을 ROM에 넣어 기판의 CPU 타이머(root counter)로 직접 시간을 재고, 결과를 화면에 숫자로 띄운다.
- 이 방법으로 측정할 수 있는 것:
  - 명령어 루프 실행 시간: CPU 실효 속도, i-cache 히트 / 미스 비용
  - GPU 프리미티브별 그리기 시간: "NS10 GPU는 1.5배" 가정 검증
  - DMA 전송 속도, EXP1 ROM 읽기 대기 사이클
  - IRQ10 / VBlank 인터럽트 간격
- 같은 테스트 ROM을 우리 코어, MAME, GHDL 시뮬에서도 돌려 세 결과를 숫자로 직접 비교한다.
- PSX용 공개 테스트(amidog, JaCzekanski ps1-tests 등)를 NS10 부팅 방식에 맞게 고쳐 쓸 수 있다.
- 주의할 점:
  - ROM이 소켓에 꽂혀 있는지, 표면 실장(TSOP 등)인지에 따라 난이도가 크게 다르다. 기판 사진으로 먼저 확인한다.
  - 원본 ROM은 반드시 먼저 덤프하고 백업한다.

### 3순위: 로직 분석기 (버스 타이밍)

- 50 MHz 버스를 보려면 200 MS/s 이상, 16채널 이상이 필요하다.
  - 예: DSLogic U3Pro16, Saleae Logic Pro 16
  - 8채널 24 MHz 저가 제품은 이 용도에 쓸 수 없다.
- 측정할 수 있는 것: ROM / 메모리 읽기 대기 사이클(/RD, /CS, WAIT), 인터럽트 핀 타이밍
- 대안: 갖고 있는 FPGA 보드와 USB-Blaster를 SignalTap 로직 분석기로 쓴다(4절).
- 프로빙 도구: QFP용 미세 피치 클립 / 마이크로 그래버, 30 AWG 와이어, 인두

### 4순위: 기타

- 영상 캡처(OSSC, RGB 캡처 장치): 실기와 코어 화면을 프레임 단위로 비교(깜빡임, 필드 문제)
- 오디오 인터페이스(48 kHz 이상): SPU 출력 파형을 코어와 비교
- 안정된 JAMMA 전원, 익스텐더, 정전기 방지 장비

### 추천 순서

1. 오실로스코프로 클럭, 비디오 타이밍, IRQ10 주기 측정. 가장 빨리 결과가 나오고 지금 열린 질문(IRQ10)에 바로 답한다.
2. ROM 라이터로 테스트 ROM 실행. 정확한 타이밍 문서화의 핵심 수단이다.
3. 버스 단위의 세부 사항이 필요해지면 로직 분석기를 마련한다(먼저 4절의 FPGA 방식 시도).

## 3. 오실로스코프만 있을 때

2절의 장비가 전부 필요한 것은 아니다. 우선순위 목록이므로 필요한 만큼 위에서부터 고르면 된다.
오실로스코프 한 대로 시작하는 것을 권한다.

### 가능한 것

| 항목 | 가능 여부 | 방법 |
|---|---|---|
| CPU / GPU 클럭 | 가능 | 수정 발진기나 클럭 핀의 주파수를 잰다. 50.7456 MHz 확인에는 충분하다. |
| 비디오 타이밍 | 가능 | H / V 동기 주기, 프레임당 라인 수, 480i 필드 순서 |
| IRQ10 주기 | 대부분 가능 | 아래 설명 참고 |
| 부팅 시간 | 가능 | 리셋 해제부터 첫 화면, 컬러바, 타이틀까지의 시간을 잰다. 우리 코어의 부팅 시간과 바로 비교할 수 있다. |
| 입력 지연 | 가능 | 한 채널은 버튼 신호, 다른 채널은 비디오 신호(밝기 변화)에 연결한다. |
| 오디오 샘플레이트 | 가능 | DAC의 LRCK(좌우 클럭) 주파수로 SPU 실제 출력 속도를 확인한다. |
| GPU 프레임 그리기 시간 | 부분 가능 | GPU와 VRAM(SGRAM) 사이의 쓰기 신호(/WE) 활동 구간을 VSync와 함께 보면 프레임마다 GPU가 그리는 시간을 대략 알 수 있다. 프리미티브 단위로는 볼 수 없다. |
| ROM 읽기 대기 사이클 | 부분 가능 | 4채널(CLK, /CS, /RD, 데이터 준비 신호)을 단발 트리거로 잡으면 읽기 한 번의 클럭 수가 보인다. 긴 구간의 통계는 어렵다. |

IRQ10 측정 방법:

- IRQ10이 외부 칩에서 CPU 핀으로 들어오는 신호라면 그 핀을 직접 잰다.
- CPU 안에서 만들어지는 신호라서 핀이 없다면 간접적으로 잰다.
  - Driller 게임은 IRQ10 처리 루틴에서 입력 포트를 읽는다.
  - 입력 버퍼 칩(예: 74HC245 계열)의 /CS나 /OE 펄스 간격을 재면 IRQ10 주기와 같다.
- 대부분의 스코프에는 측정값 통계(최소, 최대, 평균) 기능이 있어서 몇 분 동안 간격 변동을 볼 수 있다.

### 불가능한 것

- CPU 명령어 실행 시간, i-cache 히트 / 미스 비용처럼 칩 내부에서 일어나는 것. 2순위 테스트 ROM이 필요하다.
- GPU 프리미티브별 그리기 시간
- 주소 / 데이터 버스 전체 트레이스. 4채널로는 불가능하다.

### 구입 팁

- 같은 가격대의 스코프 중 일부는 MSO 옵션을 지원한다. 별도 프로브를 추가하면 16채널 디지털 입력이 생긴다.
  - 예: Siglent SDS1000X-HD + SLA1016, Rigol DHO900 계열
- 이 옵션이 있으면 3순위 로직 분석기의 상당 부분을 대신할 수 있다.
- 정확한 지원 여부는 구입 전에 모델별 사양을 확인한다.

### 정리

- 오실로스코프 한 대로 1절의 질문 중 클럭, IRQ10, 비디오 타이밍, 부팅 시간을 해결할 수 있다.
- GPU 그리기 시간과 ROM 대기 사이클도 대략적인 값은 얻을 수 있다.
- CPU / GPU 내부의 세부 타이밍만 테스트 ROM이 필요하다.

## 4. USB-Blaster 호환기 + FPGA 보드를 로직 분석기로 쓰기

USB-Blaster 자체는 로직 분석기가 아니다. FPGA와 PC를 잇는 JTAG 케이블일 뿐이고, 로직 분석기 역할은 FPGA 보드가 한다.

### 구조

```
NS10 기판 핀 ──(버퍼, 짧은 선)──> FPGA 보드 I/O 핀
                                   │ FPGA 안의 SignalTap: 신호를 내부 RAM에 기록
                                   ▼
                         USB-Blaster(JTAG) ──> PC의 Quartus SignalTap 창에서 파형 보기
```

- FPGA가 NS10 신호를 샘플링해 내부 블록 RAM에 저장하고, USB-Blaster는 저장된 데이터를 PC로 가져오기만 한다.
- SignalTap은 Quartus 17.0 Lite에 포함되어 있어 추가 비용이 없다. 디버그 빌드의 JTAG 프로브(`ns10_probe`)도 같은 경로를 쓴다.
- MiSTer(DE10-Nano)는 코어를 돌려야 하므로 쓰지 않는다. USB-Blaster와 함께 쓰는 QMTECH 보드를 쓴다.

### 시판 로직 분석기와 비교

| | FPGA + SignalTap | 시판(DSLogic, Saleae 등) |
|---|---|---|
| 채널 수 | 보드의 빈 I/O 핀 수만큼(수십 개 가능) | 16채널 |
| 샘플링 | 200~300 MHz, 또는 NS10 클럭에 맞춘 동기 캡처 | 최대 500 MS/s~1 GS/s |
| 기록 길이 | FPGA 내부 RAM 크기에 묶임(예: 32채널 × 수만~수십만 샘플) | 수백만 샘플 이상 |
| 트리거 | 주소 일치, 순서 조건 등 자유롭게 구성 | 제품 기능 범위 안 |
| 측정 로직 | 직접 넣을 수 있음 | 불가 |
| 준비 | 버퍼 회로, 배선, Quartus 프로젝트 필요 | 꽂으면 바로 사용 |

- 가장 큰 장점은 측정 로직을 직접 넣을 수 있다는 점이다.
  - 예: IRQ10 간격을 몇 분 동안 잴 때 원시 파형을 저장하지 않고, FPGA 안의 카운터로 "간격 최소 / 최대 / 평균 / 횟수"만 기록한다.
  - 이렇게 하면 RAM 크기 제한이 없어진다. 코어의 `ns10_probe`와 같은 방식이다.

### 필요한 것 (수만 원 수준)

1. **전압 변환 버퍼**:
   - FPGA I/O는 3.3 V다. NS10 기판에는 5 V 신호(ROM, TTL 로직)가 섞여 있을 수 있어 직접 연결하면 FPGA가 손상될 수 있다.
   - 3.3 V로 동작하는 74LVC245(5 V 입력 허용)를 거치는 방법이 가장 간단하다.
   - 신호 전압은 먼저 오실로스코프 / 멀티미터로 확인한다.
2. **배선**:
   - 50 MHz 신호는 15 cm 이내로 짧게 연결한다.
   - 몇 가닥마다 GND 선을 함께 둔다.
   - 두 기판의 GND를 반드시 공통으로 연결한다.
3. **프로빙**: 미세 피치 IC 클립 또는 30 AWG 와이어 납땜. 테스트 포인트, 저항 패드, 비아를 쓰면 더 쉽다.
4. **Quartus 프로젝트**: 입력 핀, 샘플링 클럭(PLL 200 MHz 또는 NS10 클럭 입력), SignalTap 인스턴스, 필요하면 카운터 / 측정 모듈.

### 한계

- 오실로스코프를 대신하지 못한다. 디지털 0 / 1만 보이고 전압, 링잉, 클럭 품질은 보이지 않는다.
- 50 MHz 버스 전체(주소 + 데이터 40개 이상)를 안정적으로 잡으려면 배선 품질이 결과를 좌우한다.
  처음에는 IRQ 핀, VSync, /CS, /RD처럼 적은 수의 제어 신호부터 시작한다.

### 다음 단계

- QMTECH 보드의 정확한 모델명(칩 이름, 예: Cyclone IV EP4CE15 / Cyclone V)과 NS10 기판 사진(측정할 칩, 테스트 포인트)을 확인한다.
- 그다음 핀 배정과 측정용 Quartus 프로젝트를 만든다.
- 측정 결과는 `docs/`에 실기 측정값 문서로 따로 정리한다.
