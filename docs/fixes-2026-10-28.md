# 2026-10-28 수정 기록: Mr. Driller G 899m 파란 화면 + 음악 반복 (BGM 스트림 경쟁 상태)

## 증상 (사용자 보고)

- 보고 시점: 2026-10-28.
- 환경: MiSTer SYSTEM10 코어, 패치 롬(시리얼 변경 + 유령 블록 수정만 적용), 혼자하기 북극 스테이지,
  MiSTer 세이브스테이트 슬롯 2.
- 상황: 800m 클리어 후, 레벨 경계에서 큰 블록이 떨어지는 899m 지점.
- 나타난 증상:
  - 화면 전체가 파란색으로 바뀐다.
  - 음악의 한 부분이 계속 반복된다.
  - 게임이 정지한다(진행 없음).
- 파란 화면의 정체: PS1 BIOS SystemError 화면.
  - BIOS SystemError 함수(`0xBFC02708`)가 화면을 그린 뒤 `0xBFC028FC` 에서 무한 루프.
  - 오류 코드 S `0x387`, CPU 예외는 AdEL, 게임 코드가 `0xF13C5002` 로 점프.
  - `0xF13C5002` 는 RAM `0x803C50A8` 에 있던 BGM 데이터 값이다.
- 음악 반복의 정체: CPU가 멈춘 상태에서 SPU가 마지막 스트림 버퍼를 계속 재생하는 것.
- 직접 원인: IRQ가 호출하는 libgpu 콜백 테이블 `0x803C4080`–`0x803C4130` 이 BGM ADPCM 데이터로 덮여 있었다.

## 원인

- 2채널, 채널당 1KB 더블 버퍼(`0x803B3500 + ch*0x800 + toggle*0x400`), 상태 기준 `0x803B34E8`,
  요청 필드 `0x803B34D8` / `0x803B34DC` (`1` 무음, `2` 다음 1KB 채움, `3` 곡 끝 / 되감기).
- 곡 끝(`pos >= len - 0x400`)에 도달하면 SPU 인터럽트(`0x80247548`)가 요청 3을 올린다.
- 메인 루프의 요청 처리기(`0x80247AE8`)가 부르는 요청 3 처리 함수(`0x80247318`)가 `s3 = len - pos` 를 계산하는데
  **`s3` 에 대한 범위 검사가 없다.** ← 여기가 원인 지점.
- 시작 경로(`0x80247EB0`)와 정지 경로(`0x8024802C`) 모두 대기 중인 요청을 지우지 않는다.
- 그래서 요청 3이 남은 채 곡이 바뀌면, 처리기는 남은 양을 **새 곡 기준**으로 계산한다
  (곡 10 기준 `0x10D520 - 0x400 = 0x10D120`, 약 1.1MB).
- 그 양을 1KB 버퍼에 밀어 넣어 RAM `0x803B3900`–`0x803C5600` 이 덮인다. 덮이는 영역에
  NAND 리맵 테이블 `0x803B4690`, 사운드 드라이버 / libspu BSS, libgpu 콜백 테이블이 포함된다.
- 다음 IRQ가 망가진 주소로 점프한다 → BIOS 오류 화면.
- 증거: 크래시 당시 `0x803B3500` 에 곡 4(BGM 7, 레벨 곡)의 마지막 조각, `0x803B3900` 부터는
  곡 10(BGM 6, `0x1F98260`)의 `start + 0x400` 부터 이어지는 연속 데이터가 있었다.

## 순정 롬에서 드러나지 않았던 이유 (추정 포함)

- **확률이 낮다 (추정).** 곡 한 바퀴 약 4000프레임 중 위험 창이 1프레임 정도여서 BGM 전환 1회당
  대략 1/4000 수준. 측정값이 아니라 곡 길이와 처리 간격으로 계산한 **추정**이다.
- **빠른 플레이로는 곡 끝에 도달하지 않는다 (추정).** 곡이 끝까지 재생되지 않으면 요청 3 자체가 없다.
- **발생해도 원인 기록이 남기 어렵다 (추정).** 무작위 멈춤처럼 보여 재현 조건을 정리하기 어렵다.
- 아케이드 판이 일본 한정 소량 출시였다는 것은 일반 정보이며 **확인 안 됨**.
- 순정 롬 실기에서의 자연 발생 기록은 찾지 않았다 / 모른다.

## 해결 방법

`s3 > 0x400` 이면 "곡이 바뀌기 전에 남은 오래된 요청" 으로 보고, 되감기 대신 평소 채움 경로로 처리한다.
정상 플레이 동작에는 변화가 없다. 적용 위치는 `0x80247398`–`0x802473A8` 로, 빈 디버그 printf 블록이 있던 자리다.

| # | 주소 | 원래 값 | 새 값 | 명령 | 의미 |
|---|---|---|---|---|---|
| 1 | `0x80247398` | `3C04801E` | `2E620401` | `sltiu v0, s3, 0x401` | `s3 < 0x401` 이면 `v0 = 1` |
| 2 | `0x8024739C` | `3C03803B` | `14400012` | `bnez v0, 0x802473E8` | 정상 크기면 정상 되감기 경로로 |
| 3 | `0x802473A0` | `246334E8` | `00000000` | `nop` | 지연 슬롯 |
| 4 | `0x802473A4` | `00151080` | `10000054` | `b 0x802474F8` | 비정상(큰 `s3`)이면 평소 채움 경로로 |
| 5 | `0x802473A8` | `00431021` | `00000000` | `nop` | 지연 슬롯 |

- 별도 롬 패치 도구(`D:\My_App_Project\driller-rom-patch`)의 `--fix` 로 적용한다. 유령 블록 15워드 + BGM 5워드 = **20워드**, 구간 5 페이지 4569 재암호화.
- 새 패치 롬 0.8e: CRC `76101f53`, SHA1 `0b5d9f72cb25cc28e3cb1c14a4930e2c7e8264d8`, 시리얼 `999999-000301`.
  이전 버전 롬(유령 블록 15워드만 적용된 상태)에서 이 20워드 상태로 올린다.
- MiSTer: 롬 zip 교체 + MRA crc 갱신, 기존 파일은 백업 폴더(`/media/fat/backup_20261028/`)에 보관.
- GroovyMAME: CRC 갱신 후 빌드 (커밋하지 않음).
- FPGA 코어(RTL)는 수정하지 않았다.

## 검증

- GroovyMAME: 세이브스테이트에서 곡 시작 순간 요청 3 을 강제로 발생시킨다.
  - 순정 롬 / 유령 블록만 적용한 롬: **27프레임 후 BIOS 무한 루프** (MiSTer 증상과 같음).
  - 수정 코드: 계속 재생됨.
- 산소 값을 고정(죽지 않게)하고 60000프레임 진행, 곡 되감기 17회 → 무크래시.
  즉 **곡 반복 자체는 안전**하다.
- 콜드 부팅 검증: 새 롬은 RAM 에 20워드가 모두 존재하고, 강제 경쟁 상황에서도 4500프레임 무크래시.
  이전 롬은 28프레임 후 BIOS 루프.
- 롬 패치 도구의 검증 스크립트 86개 통과.
- 주의: MAME 는 NAND 를 nvram 폴더(`nand0/1/2`)에 저장하고 다음 실행에서 롬 대신 그 저장본을 사용한다.
  따라서 **롬 교체 후 테스트는 반드시 새 nvram 폴더로** 해야 한다.
- 자세한 분석과 근거는 `docs/bgm-loop-glitch.md` 를 보라.

# 2026-10-28 추가: Mr. Driller G 점수/메모리 분석 문서 (코드 변경 없음)

## 목적 (사용자 요청)

원본 롬(mrdrilrg)에서 India / America / Egypt / North 1인 플레이 최고 점수를 얻는 방법, 레벨별 수치, 이론상 최고 점수, 캐릭터 성능을 정리한다. 다음 세션에서 쓸 수 있도록 메모리 주소도 문서로 남긴다.

## 방법

- GroovyMAME + Lua(산소 고정 0x80369CA0, 쓰기 탭, RAM 덤프)로 실측하고, capstone 역어셈으로 확인했다.
- 사용자 세이브 상태는 복사본만 사용했다.

## 결과 요약

- 점수는 RAM에 저장되지 않는다. 0x80212AE4가 카운터를 매 프레임 합산한다.
- 클리어 보너스: 목숨 ×30,000, 시간(초당 500점 감소), 퍼펙트 에어 50,000(캡슐 전부). India 자동 완주로 계산식이 일치함을 확인했다.
- 캡슐은 실제로 23%를 회복한다. 산소 최대치는 102%다.
- 가설 수정: 처음에는 "캐릭터별 드릴 속도 값이 없다"고 결론냈다. 이후 P+0xAC(파낸 칸 사라짐 시간)를 발견했다. 타이조는 3프레임, 나머지 캐릭터는 15프레임이다. 이 값까지 맞춰 다시 측정하니 타이조가 아래로 7~10% 빠르게 내려갔다. 처음 비교에서는 이 값을 바꾸지 않았기 때문에 차이를 놓쳤다.
